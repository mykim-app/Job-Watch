# 전산·통신직 채용 정보 모니터링

공공기관·지방공기업·공무원·대학 채용공고를 **하루 세 번(09시·13시·17시)** 훑어서,
전산·통신 분야 중 **어제까지 없던 공고만** 골라 웹페이지에 올리고 메일로 보냅니다.

- **실행**: 시놀로지 NAS 작업 스케줄러 + 도커
- **화면**: GitHub Pages — https://mykim-app.github.io/Job-Watch/
- **메일**: 한국 기준 근무일에만 발송. 휴일에 찾은 공고는 다음 근무일 메일에 합쳐서 나감

> GitHub Actions 로는 돌릴 수 없습니다. GitHub 서버(미국)에서 국내 공공 사이트가
> 전부 connect timeout 으로 막힙니다. 확인 끝난 사항이라 NAS 실행이 유일한 방법입니다.

그 출처만 빠지고 나머지는 정상 수집되며, 실패한 곳은 웹페이지 하단에 표시됩니다.

### 출처별로 다르게 거르는 부분

- **잡알리오·클린아이**: NCS 직무를 '정보통신'으로 지정해 조회합니다.
  제목에 '전산'이 없는 공고("○○공사 하반기 신입직원 채용")도 잡힙니다.
- **대학교직원신문**: 제목에 직종이 안 드러나면 **상세 본문을 열어** 모집분야를 확인합니다.
  한 번 확인한 글은 `.cache` 에 기록해 다시 열지 않습니다.
- **서울일자리포털·사람인·고용24**: 민간기업이 대부분이라
  기관명이 `public_org_patterns`(공사·공단·재단·(재)·협회·진흥원 …)에 걸리는 것만 남깁니다.

## 2. 어떻게 거르는가

기관마다 직종코드 기준이 제각각이라 **제목·직무분류 글자 매칭이 주**이고 NCS 분류는 보조입니다.
`config.yaml` 의 `filters` 에서 조절합니다.

```yaml
filters:
  include:              # 이 중 하나라도 걸리면 후보
    - 전산
    - 정보통신
    - 정보보안
  exclude:              # 무조건 제외 (직무 자체가 다름, 결과 발표 등)
    - 조리
    - 미화
    - 합격자
  exclude_employment:   # 고용형태 때문에 제외
    - 비정규직
    - 기간제
    - 인턴
    - 계약직
  keep_employment:      # 위에 걸려도 이 말이 함께 있으면 살린다
    - 정규직
    - 무기계약
    - 공무직
```

### `exclude` 와 `exclude_employment` 의 차이

`exclude` 는 무조건 버립니다. `exclude_employment` 는 **같은 공고에서 정규직도 함께 뽑으면 살립니다.**
"○○공사 기간제 및 정규직 전산직 채용" 같은 공고를 놓치지 않기 위한 규칙입니다.

겹치는 글자도 처리합니다.

- `비정규직` 안의 `정규직` 때문에 살아나지 않습니다
- `무기계약직` 이 `계약직` 에 걸려 죽지 않습니다

### 날짜 조건

- `lookback_days: 30` — 최근 30일 안에 올라온 공고만 담습니다
- `drop_closed: true` — 접수가 끝나면 목록에서 자동으로 빠집니다(마감 당일까지는 남음)
- 마감일이 없는 상시채용 공고는 계속 남습니다

## 3. 중복 처리

- 같은 공고가 매번 잡혀도 **처음 본 날짜**를 기억해 다시 신규로 치지 않습니다
- 여러 출처에 같은 공고가 올라오면 **먼저 발견한 쪽만** 화면에 남습니다
  (기관명의 `(주)`·`재단법인` 표기, 제목 끝의 `(~09. 04.(금))` 마감일 표기를 떼고 비교)
- 기록 자체는 지우지 않습니다. 지우면 다음 날 다시 신규로 잡히기 때문입니다

## 4. 보관 기간

**로그와 공고 데이터가 같은 기간을 씁니다.** 기본 365일입니다.

```
.env 에 KEEP_DAYS=180  →  로그·데이터 둘 다 180일
```

로그는 `logs/2026-W36.log` 처럼 **주 단위**로 쌓이고, 기간이 지나면 실행 때마다 정리됩니다.

## 6. NAS 운영

### 수동 실행

```bash
sudo -i
docker run --rm -e TZ=Asia/Seoul -v /volume1/docker/job-watch:/app -w /app \
  --env-file /volume1/docker/job-watch/.env python:3.12 bash /app/run.sh
tail -40 /volume1/docker/job-watch/logs/$(date +%G-W%V).log
```

### git 명령 (NAS 에는 git 이 없어 컨테이너를 빌려 쓴다)

```bash
alias g='docker run --rm -v /volume1/docker/job-watch:/app -w /app python:3.12 git -c safe.directory=/app'
g status --short
g log --oneline -5
```

### 설정 수정

**GitHub 웹에서 고치세요.** `run.sh` 가 실행 전에 `git pull` 을 하므로 다음 실행 때 반영됩니다.
NAS 에서 직접 고치면 충돌이 납니다. `.env` 만 NAS 전용입니다.

### `.env` 항목

```
SEOUL_API_KEY=...        서울 열린데이터광장 일반 인증키
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=보내는주소
SMTP_PASS=앱비밀번호16자리
MAIL_TO=받는주소1,받는주소2      ← 쉼표로 구분 (세미콜론은 안 됨)
SITE_URL=https://mykim-app.github.io/Job-Watch/
KEEP_DAYS=365            (선택) 로그·데이터 보관 기간
```

## 7. 자주 하는 작업

### 데이터 초기화

GitHub 에서 `docs/data/postings.json` 을 아래로 바꾸고 Commit 합니다.

```json
{ "updated_at": "", "postings": [] }
```

모든 공고가 신규로 다시 잡혀 **다음 근무일 메일이 한 번 크게 옵니다.** 그 뒤로는 정상입니다.

### 특정 출처가 왜 0건인지 볼 때

`config.yaml` 에 수집처 키를 넣으면 단계별 탈락 수와 예시가 로그에 남습니다.

```yaml
diagnose: [seoul]
```

쓸 수 있는 키: `alio_web` `cleaneye` `gojobs` `procollege` `uman` `seoul` `saramin` `worknet`
확인이 끝나면 `diagnose: []` 로 되돌립니다.

### 화면 기간 조절

`docs/index.html` 맨 위의 한 줄입니다.

```javascript
const WINDOW_DAYS = 30;          // 화면에 보여줄 기간
const RUN_HOURS = [9, 13, 17];   // 작업 스케줄러에 걸어둔 시각
```

## 8. 알아두면 좋은 것

- 실행에 **3~4분** 걸립니다. 요청 사이에 간격을 두어 503 을 피하기 때문입니다.
- **신규 0건이면 메일이 안 옵니다.** 조용한 날은 원래 조용한 겁니다.
  잘 돌고 있는지는 웹페이지 하단의 `마지막 확인` 시각으로 봅니다.
- **메일 발송이 실패하면 대기 목록에 남았다가 다음 실행 때 다시 시도합니다.**
- 대학교직원신문은 **첨부파일에만 내용이 있는 공고**를 못 거릅니다.
  본문에 "붙임 참조"만 쓰고 HWP 에 모집분야를 넣는 경우입니다.
- 서울일자리포털은 **공고 원문 주소를 주지 않아** 목록에서 링크가 안 걸립니다.
- 인크루트·잡코리아·잡플래닛은 각각 robots.txt 나 이용약관으로 자동 수집을
  금지하고 있어 넣지 않았습니다.
